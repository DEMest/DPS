# Задача C3

## Условие

Реализовать параллельный вариант `filter` на futures. Каждая future должна обрабатывать
блок элементов, а не один элемент. Входная последовательность может быть как конечной,
так и бесконечной, поэтому фильтр должен быть ленивым и при этом работать быстрее за счёт
параллельности.

Покрыть код модульными тестами. Показать выигрыш по времени с помощью `time`.

## Решение

[src/c3/core.clj](src/c3/core.clj), функция `pfilter`:

```clojure
(pfilter even? (range 10))           ;; => (0 2 4 6 8)
(pfilter even? 100 (range 10))       ;; размер блока — 100 элементов
(take 5 (pfilter odd? (range)))      ;; => (1 3 5 7 9), бесконечный вход
```

* `partition-all` лениво режет вход на блоки по `block-size` элементов (по умолчанию 1000);
* `map` превращает каждый блок в `future`, которая фильтрует его обычным `filter` и сразу
  вычисляет результат (`doall`). `map` тоже ленивый, поэтому future создаётся только
  когда до её блока дошла очередь;
* `step` собирает результат: берёт значение очередной future (`deref`) и лениво
  приклеивает к нему (`concat`) результат остальных блоков. Вместе с этим он держит
  вторую ссылку на последовательность future, сдвинутую на число ядер (`drop n`), и
  на каждом шаге продвигает её на один элемент. Так вперёд всегда запущено столько
  блоков, сколько ядер у процессора, и пока забирают один блок, остальные уже считаются.
  Этот приём взят из реализации `pmap`.

Порядок элементов сохраняется: блоки склеиваются в том же порядке, в каком шли во входе.
Пока результат не нужен, вход не читается вовсе; при чтении результата вычисляется не
больше `n + 1` блоков вперёд, поэтому бесконечный вход не приводит к зависанию.

## Выигрыш по времени

`lein run` фильтрует простые числа нарочно медленной проверкой (деление на все числа от 2
до n−1) обычным `filter` и `pfilter` и печатает время каждого варианта. Перед замерами
обе функции несколько раз прогреваются, чтобы JIT уже скомпилировал код.

На 12-ядерном процессоре:

```
$ lein run
Простые числа меньше 30000:
filter:  "Elapsed time: 2103.079708 msecs"
pfilter: "Elapsed time: 326.5535 msecs"
Первые 3000 простых из бесконечной последовательности (range):
filter:  "Elapsed time: 1763.209125 msecs"
pfilter: "Elapsed time: 296.291333 msecs"
```

Выигрыш — примерно в 6 раз. Меньше числа ядер, потому что блоки неравные по стоимости
(чем больше числа, тем дольше проверка), а результаты забираются строго по порядку: новый
блок запускается, только когда забрали самый старый. С бесконечным входом ещё и
считаются впрок блоки, которые потом не понадобятся.
На лёгком предикате вроде `even?` выигрыша не будет: накладные расходы на future и
разбиение на блоки больше самой работы.

## Тесты

[test/c3/core_test.clj](test/c3/core_test.clj):

* результат совпадает с `filter` при разных размерах блока, неполном последнем блоке,
  пустом входе и `nil`;
* бесконечный вход: `take`, `nth`, `first`;
* ленивость: пока результат не нужен, вход не читается, а для первого элемента
  читается не больше `n + 2` блоков;
* параллельность: предикат со сном вызывается из нескольких потоков одновременно.

## Что нужно

JDK 21 и [Leiningen](https://leiningen.org) (на macOS — `brew install leiningen`).
Clojure отдельно ставить не нужно, Leiningen скачает его при первом запуске.

## Запуск

Из этой папки (`C3`):

```
lein test   # тесты
lein run    # замеры времени filter и pfilter
```

```
$ lein test
Ran 5 tests containing 18 assertions.
0 failures, 0 errors.
```
