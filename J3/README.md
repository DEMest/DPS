# J3. Асинхронный обход ресурсов HTTP-сервера

Паук обходит сервер из `Task_J3-server.jar`: начинает с `/`, идёт по путям из `successors` и в конце
печатает все сообщения в лексикографическом порядке. Каждый запрос выполняется в отдельной
виртуальной нити.

## Запуск

Нужен JDK 21+. Команды выполняются из папки `J3`.

Сервер (jar в репозиторий не добавлен, его нужно положить в папку `J3`):

```
java -jar Task_J3-server.jar IvanIvanov
```

Порт серверу передавать нельзя: с ним сервер падает с `ClassCastException`, поэтому он всегда
работает на 8080.

Паук, в другом терминале:

```
./gradlew jar                      (Windows: gradlew.bat jar)
java -jar build/libs/J3.jar > messages.txt
```

Адрес сервера можно передать аргументом, по умолчанию `http://localhost:8080`:

```
java -jar build/libs/J3.jar http://localhost:8080
```

Сообщения выводятся в stdout по одному на строку, итог (сколько сообщений, ошибок и время) в stderr.
Для `IvanIvanov` получается 1001 сообщение примерно за 90 секунд. В начале вывода идут пустые
строки: сервер присылает и пустые сообщения, а пустая строка при сортировке оказывается первой.

## Как работает

- Для каждого нового пути запускается виртуальная нить (`Executors.newVirtualThreadPerTaskExecutor`),
  поэтому все запросы ждут ответа одновременно и обход занимает время самой длинной цепочки,
  а не сумму всех задержек.
- Пройденные пути лежат в `ConcurrentHashMap.newKeySet()`. `add` возвращает `false`, если путь уже
  есть, поэтому каждый URL запрашивается один раз, даже если его нашли две нити сразу.
- Нить ждёт нити, которые сама запустила. Когда закончилась задача для `/`, закончен весь обход.
- Неудачный запрос повторяется до трёх раз. Если не помогло, путь считается ошибкой, а обход
  остальных продолжается.

## Тесты

```
./gradlew test
```

Тесты поднимают локальный HTTP-сервер и проверяют, что собраны все сообщения в правильном
порядке, каждый путь запрошен один раз, запросы идут параллельно и битая ссылка не ломает обход.
