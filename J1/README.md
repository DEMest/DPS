# Task J1: сервер генерации ключей

Микросервис, выдающий по TCP пары ключей RSA и сертификаты X509 на имя, переданное клиентом,
и клиент к нему.

> **Внимание.** Раздача приватных ключей по сети недопустима с точки зрения безопасности.
> Это учебная задача, такой подход нельзя применять в реальных системах.

## Как это устроено

```
                 ┌────────────┐
   TCP-соединения│  acceptor  │  Selector, OP_ACCEPT
        ────────>│   (нить)   │  раздаёт соединения по кругу
                 └─────┬──────┘
                       v
            ┌──────────────────────┐   очередь задач    ┌──────────────────┐
            │  io-1 … io-N (нити)  │ ─────────────────> │  пул keygen-1..M │
            │ Selector, OP_READ /  │                    │ KeyPairGenerator │
            │ OP_WRITE, разбор     │ <───────────────── │ + подпись X509   │
            │ имени, отправка      │  очередь ответов   └──────────────────┘
            └──────────────────────┘
```

* **Нити ввода-вывода** (`--io-threads`, по умолчанию 1) мультиплексируют ввод-вывод через
  `java.nio.channels.Selector`: принимают имя (ASCII до нулевого байта) и отправляют ответ.
  Нить ОС на клиентское соединение не создаётся, поэтому сотни одновременных клиентов
  (включая «медленных») обслуживаются несколькими нитями.
* **Генерирующие нити** — фиксированный пул (`--threads`, по умолчанию по числу ядер).
  Задачи попадают в них через очередь пула, результат кладётся в очередь нити ввода-вывода
  (`IoWorker.resultReady` + `Selector.wakeup`). Генерирующая нить блокируется только при
  отсутствии работы, но никогда — на передаче результата клиенту.
* **Хранилище** (`KeyRegistry`) — `ConcurrentHashMap<String, CompletableFuture<KeyResult>>`
  в оперативной памяти. Первый запрос имени создаёт future и ставит задачу в очередь;
  повторные запросы — в том числе пришедшие раньше, чем закончится генерация, — подписываются
  на тот же future и получают тот же самый ключ. Если клиент ушёл, не дождавшись ответа,
  сгенерированный ключ всё равно остаётся в памяти.
* **Сертификат** выпускается через `org.bouncycastle.cert.X509v3CertificateBuilder`:
  Issuer Name фиксирован настройками сервиса, Subject Name — `CN=<имя клиента>`,
  подпись `SHA256withRSA` ключом УЦ, прочитанным из файла при запуске.

## Протокол

```
запрос:  <имя в ASCII> 0x00

ответ:   byte  status                    0 — успех, 1 — ошибка
         успех:  int32 len, PEM приватного ключа (PKCS#8)
                 int32 len, PEM сертификата
         ошибка: int32 len, текст ошибки в UTF-8
```

Числа — big-endian. После отправки ответа сервер закрывает соединение.

## Сборка

Нужен **JDK 21 или новее** — в клиенте и тестах используются виртуальные нити.
Проверить: `java -version` должна показать 21+. Частая ловушка в WSL и Linux —
несколько установленных JDK, когда `JAVA_HOME` указывает на одну версию, а `java`
в `PATH` берётся из другой: Gradle тогда соберёт классы под 21, а запуск упадёт с
`UnsupportedClassVersionError ... class file version 65.0`.

Проект использует **Lombok** — только на этапе компиляции (`compileOnly`), внутрь готового
jar он не попадает. Из аннотаций применяются `@Slf4j` (поле-логгер), `@RequiredArgsConstructor`
(конструкторы, которые только присваивают поля) и `@NoArgsConstructor(access = PRIVATE)`
(закрытые конструкторы служебных классов). Из командной строки ничего настраивать не нужно;
в IntelliJ IDEA нужен плагин Lombok — он входит в поставку начиная с версии 2020.3.

Из этой папки (`J1`), в cmd или PowerShell:

```
gradlew.bat fatJar
```

В bash, WSL или Git Bash — `./gradlew fatJar`. Дальше в примерах пишется `gradlew.bat`,
подразумевается любой из двух вариантов.

Получится один самодостаточный файл `build/libs/J1-all.jar` (внутри лежит и BouncyCastle),
который запускается обычной командой `java -jar` с параметрами:

```
java -jar build/libs/J1-all.jar <подкоманда> [опции]
```

Подкоманды: `gen-ca`, `server`, `client`; у каждой есть `--help`. Команды ниже рассчитаны
на запуск из папки `J1` — путь к jar в них указан относительно неё.

Альтернативы, если jar собирать не хочется:

```
gradlew.bat installDist                      # скрипты build/install/J1/bin/J1.bat и J1
gradlew.bat run --args="server --ca-key ca.key --ca-cert ca.crt --port 9000"
java -cp "build/classes/java/main;<пути к bcpkix и bcprov>" org.example.Main server ...
```

Можно запускать и конкретный класс-точку входа вместо подкоманды — тогда первый аргумент не
нужен:

```
java -cp build/libs/J1-all.jar org.example.server.ServerMain --ca-key ca.key --ca-cert ca.crt --port 9000
java -cp build/libs/J1-all.jar org.example.client.ClientMain --name alice --port 9000
java -cp build/libs/J1-all.jar org.example.ca.CaMain --out-key ca.key --out-cert ca.crt
```

## Запуск

### 1. Ключ удостоверяющего центра (делается один раз, заранее)

```
java -jar build/libs/J1-all.jar gen-ca --issuer "CN=DPS Key Service CA, O=NSU, C=RU" --out-key ca.key --out-cert ca.crt
```

| Опция | Назначение |
|---|---|
| `--issuer <DN>` | Issuer Name УЦ (по умолчанию `CN=DPS Key Service CA, O=NSU, C=RU`) |
| `--key-size <бит>` | длина ключа подписи, по умолчанию 4096 |
| `--validity-days <дни>` | срок действия сертификата УЦ, по умолчанию 3650 |
| `--out-key`, `--out-cert` | куда записать ключ и сертификат |

### 2. Сервер

```
java -jar build/libs/J1-all.jar server --ca-key ca.key --ca-cert ca.crt --port 9000 --threads 8
```

| Опция | Назначение |
|---|---|
| `--ca-key`, `--ca-cert` | файлы ключа и сертификата УЦ (обязательны) |
| `--issuer <DN>` | Issuer Name выдаваемых сертификатов; по умолчанию Subject Name сертификата УЦ |
| `--port <порт>` | TCP-порт, по умолчанию 9000 |
| `--bind <адрес>` | адрес прослушивания, по умолчанию `0.0.0.0` (подключение с других компьютеров) |
| `--threads <n>` | число генерирующих нитей, по умолчанию число ядер |
| `--io-threads <n>` | число нитей ввода-вывода, по умолчанию 1 |
| `--key-size <бит>` | длина приватного ключа RSA, по умолчанию 8192 |
| `--validity-days <дни>` | срок действия выдаваемых сертификатов, по умолчанию 365 |
| `--backlog <n>` | длина очереди входящих соединений, по умолчанию 512 |
| `--config <файл>` | properties-файл с теми же именами параметров (см. `server.properties.example`) |
| `--verbose` | подробный журнал |

Параметры командной строки имеют приоритет над конфигурационным файлом.

### 3. Клиент

```
java -jar build/libs/J1-all.jar client --name alice --host localhost --port 9000 --out-dir keys
```

Сохраняет `keys/alice.key` (PEM PKCS#8) и `keys/alice.crt` (PEM X509). Если сервер на другом
компьютере, вместо `localhost` подставляется его IP-адрес или DNS-имя, например
`--host 192.168.1.10`.

| Опция | Назначение |
|---|---|
| `--name <имя>` | имя, передаваемое серверу (оно же Subject Name сертификата) |
| `--host <адрес>` | адрес или DNS-имя сервера, по умолчанию `localhost` |
| `--port <порт>` | порт сервера, по умолчанию 9000 |
| `--out-dir <путь>` | каталог для файлов `.key` и `.crt` |
| `--delay <сек>` | пауза между отправкой запроса и чтением ответа — имитация медленного клиента |
| `--abort` | завершиться, не читая ответ — имитация аварийного завершения клиента |
| `--clients <n>` | нагрузочный режим: n одновременных клиентов в одном процессе |
| `--unique-names` | в нагрузочном режиме давать каждому клиенту своё имя |
| `--timeout <мс>` | таймаут соединения и чтения, по умолчанию 600000 |

Имя, адрес и порт можно передавать и позиционно: `java -jar build/libs/J1-all.jar client alice 192.168.1.10 9000`.

Примеры проверок:

```
java -jar build/libs/J1-all.jar client --name bob   --port 9000 --delay 10          # медленный клиент
java -jar build/libs/J1-all.jar client --name carol --port 9000 --abort             # аварийное завершение
java -jar build/libs/J1-all.jar client --name load  --port 9000 --clients 150 --unique-names
```

## Тесты

```
gradlew.bat test
```

Интеграционные тесты (`src/test/java/org/example/KeyServerTest.java`) поднимают сервер
в том же процессе с ключами 1024 бита и проверяют:

* выдачу ключа и сертификата, подписанного УЦ, с Subject Name = имя клиента;
* повторную выдачу того же ключа по тому же имени (генерация ровно один раз);
* 50 одновременных запросов одного имени до окончания генерации — один ключ на всех;
* 120 одновременных клиентов с разными именами;
* медленный клиент не задерживает остальных;
* аварийно завершившийся клиент не ломает сервер, ключ остаётся в памяти;
* пустое имя — ответ с ошибкой.

### Если путь к домашнему каталогу содержит кириллицу

На Windows с кириллическим именем пользователя Gradle не может запустить тестовый worker:
classpath передаётся файлом-аргументом из `C:\Users\<Имя>\.gradle\.tmp\…`, и JVM читает его
в другой кодировке (`Could not find or load main class …GradleWorkerMain`). Обходится
указанием Gradle home на ASCII-путь:

```
gradlew.bat -g ..\.gradle-home test
```

Сам сервер и клиент от этого не зависят.

## Структура кода

| Файл | Назначение |
|---|---|
| `org/example/Main.java` | выбор подкоманды `gen-ca` / `server` / `client` |
| `org/example/ca/CaGenerator.java` | создание ключа и самоподписанного сертификата УЦ |
| `org/example/ca/CertificateAuthority.java` | чтение ключа подписи, выпуск сертификатов X509 |
| `org/example/server/KeyServer.java` | сборка сервера: сокет, нити ввода-вывода, акцептор |
| `org/example/server/Acceptor.java` | приём соединений, раздача их нитям ввода-вывода |
| `org/example/server/IoWorker.java` | Selector-цикл, очередь новых соединений и очередь ответов |
| `org/example/server/ClientConnection.java` | состояние соединения: чтение имени, отправка ответа |
| `org/example/server/KeyRegistry.java` | пул генерирующих нитей и хранилище выданных ключей |
| `org/example/client/KeyClient.java` | клиентская часть протокола и запись файлов |
| `org/example/common/Protocol.java` | формат запроса и ответа |
| `org/example/common/KeyResult.java` | пара «PEM ключа + PEM сертификата» |
| `org/example/common/Logging.java` | уровень журналирования по ключу `--verbose` |
| `resources/logback.xml` | формат сообщений журнала (SLF4J + Logback) |

## Журналирование

Используется SLF4J с реализацией Logback. Формат и приёмники задаются в
`src/main/resources/logback.xml`:

```
12:58:47.230 INFO  [main] KeyServer - Сервер слушает 0.0.0.0:9000; генерирующих нитей: 2, …
12:58:49.741 DEBUG [io-1] ClientConnection - Запрос имени "alice" от /127.0.0.1:49106
12:58:50.666 INFO  [keygen-1] KeyRegistry - Ключ для "alice" готов за 0,90 с
```

По умолчанию выводится уровень INFO, ключ `--verbose` переключает корневой логгер в DEBUG
(видно каждое соединение и его завершение). Кодировка консоли берётся из системного свойства
`stdout.encoding`, поэтому русский текст читается и в cmd, и при перенаправлении в файл.
